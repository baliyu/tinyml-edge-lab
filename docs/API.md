# Interfaces of tinyml-edge-lab

This is the reference for the parts of the repository that other code is meant to call: the C interfaces that run on the SparkFun Edge, the serial
protocol the firmware speaks, the Python package `tinyml_lab`, and the command-line tools. It is a portfolio project, not a published library, so
there is no promise of backward compatibility except where it is said: the serial protocol is versioned (see section 2).

Three of the four sections below are **generated** from the code (the parts between `<!-- api:... -->` markers), by `python scripts/make_api_docs.py`.
A test fails if they are out of date, if a public function of a supported module is missing from the reference, or if it has no docstring. The
explanations around them are written by hand, and a second test checks that the serial-protocol section still matches what `main.c` prints.

## 1. On the device: the C interfaces

Three headers, from the bottom up:

| Header | What it gives you |
|---|---|
| `edge_features.h` | The features of **one** 128-sample window: `ef_raw_features` (40 values) and `ef_motion_features` (37 values). |
| `gesture_pipeline.h` | The **stream**: raw timestamped samples in, a gesture number out, once per window. It calls the features and the model. |
| `gesture_model.h` | The trained model: `gesture_model_predict()` and the gesture names. Generated by `scripts/export_gesture_model.py`; never edited by hand. |

### Conventions
- Plain C (the chain uses `_Static_assert`, so C11 or GNU C). No `malloc`, no global state, no hardware access: the same files run on the Cortex-M4F and,
  in the tests, on the PC.
- One `gp_state` per sample stream. Nothing is reentrant: call `gp_push` from one context only (not from an interrupt and the main loop at once).
- Units: acceleration in **milli-g** (integers from the sensor), time as a free-running **32-bit tick counter** of `tick_hz` ticks per second. The counter may wrap.
- `ef_real` is `float` by default. The tests also build with `-DEF_REAL=double` to show that the algorithm equals the Python one to machine precision.
- Memory: the chain's whole state is one `gp_state`; sizes measured with the ARM compiler are recorded in `firmware/sparkfun_edge/gesture_demo/README.md`.

### The contract of `gp_push`
- It returns **1** when this sample completed a window; `gp_class()` is then that window's gesture, an index into `GESTURE_CLASS_NAMES`. Otherwise 0.
- Samples are resampled by linear interpolation onto an exact 50 Hz grid, as `tinyml_lab.edge_gestures.resample_to_grid` does. Windows are 128 grid samples, a new one
  every 64 (so every 1.28 s).
- A hole longer than `GP_MAX_GAP_STEPS` grid steps (0.24 s), or time running backwards, is **not** interpolated over: the half-built window is dropped and a new one starts
  (`gp_restarts()` counts them). A shorter hole is interpolated over.
- A repeated timestamp is ignored (`gp_ignored()` counts them).
- There is no error return from `gp_push`. Failures of the sensor itself are the caller's to count, as `main.c` does. `gp_init` returns -1 for a null state or a tick rate outside
  1 to 100,000,000.

#### `firmware/sparkfun_edge/gesture_features/edge_features.h`

```c
/* Window features for the desk-gesture classifier, in plain C99: no malloc, no libm beyond sqrt.
 *
 * Port of tinyml_lab.features.window_features / tinyml_lab.edge_gestures.feature_matrix. The Python version is the
 * reference: tests/test_edge_features_c.py compiles this file and compares it with Python on real and synthetic windows.
 *
 * Build as float (what the board runs, the default) or as double (used on the PC to prove the algorithm matches Python):
 *     gcc -DEF_REAL=double -c edge_features.c
 *
 * Input: one window of EF_WINDOW samples, x/y/z interleaved (x0,y0,z0,x1,y1,z1,...), in milli-g, sampled at EF_FS_HZ.
 * Output: the features in exactly the order of tinyml_lab.edge_gestures.feature_names_for("raw") / ("motion").
 */
#ifndef EDGE_FEATURES_H
#define EDGE_FEATURES_H

#ifdef __cplusplus
extern "C" {
#endif

#ifndef EF_REAL
#define EF_REAL float
#endif
typedef EF_REAL ef_real;

#define EF_WINDOW 128               /* samples per window (2.56 s at 50 Hz); must be a power of two <= the cosine table */
#define EF_FS_HZ 50.0               /* the sampling rate the features assume */
#define EF_BANDS 4                  /* spectral bands, equal width from 0 to fs/2 */
#define EF_CHANNEL_FEATURES 10      /* per channel: mean, std, rms, min, max, dom_freq, band0..band3 */
#define EF_RAW_FEATURES 40          /* x, y, z and the vector magnitude, as measured */
#define EF_MOTION_FEATURES 37       /* the window mean removed first; x, y, z means are not used */

void ef_raw_features(const ef_real *xyz, ef_real *out);       /* out: EF_RAW_FEATURES values */
void ef_motion_features(const ef_real *xyz, ef_real *out);    /* out: EF_MOTION_FEATURES values */

#ifdef __cplusplus
}
#endif
#endif
```

#### `firmware/sparkfun_edge/gesture_demo/gesture_pipeline.h`

```c
/* The whole on-device chain for the desk-gesture classifier, in plain C99 with no malloc and no hardware access:
 *
 *   raw samples (a 32-bit tick count and x/y/z in milli-g, at the sensor's own, slightly uneven rate)
 *     -> linear resampling onto an exact 50 Hz grid -> 128-sample windows, a new one every 64 samples
 *     -> window features (edge_features.c) -> the trained model (gesture_model.c) -> a gesture number.
 *
 * It does the same job as tinyml_lab.edge_gestures (resample_to_grid, make_windows, feature_matrix) followed by the model's
 * predict(). tests/test_gesture_pipeline_c.py and scripts/check_gesture_pipeline.py hold it to that on the PC, so the board
 * only has to call gp_push() once per sensor sample.
 *
 * Time is kept as an integer in units of 1/(50 * tick_hz) second. In those units one grid step is exactly tick_hz, so the
 * grid does not drift or round, whatever the tick rate (3 MHz internal oscillator or 32.768 kHz crystal).
 *
 * Usage:
 *     static gp_state g;
 *     gp_init(&g, tick_hz, 0);
 *     ... for every sensor sample:  if (gp_push(&g, ticks, x_mg, y_mg, z_mg)) use GESTURE_CLASS_NAMES[gp_class(&g)];
 */
#ifndef GESTURE_PIPELINE_H
#define GESTURE_PIPELINE_H

#include <stddef.h>
#include <stdint.h>

#include "edge_features.h"
#include "gesture_model.h"

#ifdef __cplusplus
extern "C" {
#endif

#define GP_FS_HZ 50                 /* the grid every window is cut from; the features and the model assume it */
#define GP_WINDOW EF_WINDOW         /* samples per window (2.56 s) */
#define GP_STEP 64                  /* a new window every 64 samples: 50 % overlap */
#define GP_MAX_GAP_STEPS 12         /* a hole longer than 12 grid steps (0.24 s) is not interpolated over: the window restarts */

typedef struct {
    uint32_t tick_hz;               /* ticks per second of the timer that stamps the samples */
    uint32_t skip;                  /* grid samples to drop after start-up, before the first window */
    uint32_t last_raw;              /* the last 32-bit tick count seen */
    uint64_t u_prev;                /* time of the previous sample, in units of 1/(50 * tick_hz) s since the first */
    uint32_t grid_k;                /* index of the next grid sample to produce */
    uint32_t to_skip;               /* start-up samples still to drop */
    uint32_t fill;                  /* samples in the window being built */
    uint32_t windows;               /* windows classified so far */
    uint32_t restarts;              /* times a long gap restarted the window */
    uint32_t ignored;               /* samples dropped because they repeated the previous timestamp */
    int32_t prev[3];                /* the previous sample, milli-g */
    int last_class;                 /* the last window's gesture number, or -1 */
    int started;                    /* has a first sample defined time zero? */
    ef_real buf[GP_WINDOW * 3];     /* the window being built, x/y/z interleaved */
    ef_real feat[GESTURE_N_FEATURES];
} gp_state;

/* Returns 0, or -1 for a null state or a tick rate outside 1 .. 100 000 000. skip: grid samples dropped after start-up. */
int gp_init(gp_state *g, uint32_t tick_hz, uint32_t skip);

/* One sensor sample. ticks is the free-running 32-bit counter (it may wrap); x, y, z are milli-g.
 * Returns 1 when this sample completed a window and gp_class() holds that window's gesture, otherwise 0. */
int gp_push(gp_state *g, uint32_t ticks, int32_t x_mg, int32_t y_mg, int32_t z_mg);

int gp_class(const gp_state *g);                /* the last window's gesture number, an index into GESTURE_CLASS_NAMES, or -1 */
uint32_t gp_windows(const gp_state *g);
uint32_t gp_restarts(const gp_state *g);
uint32_t gp_ignored(const gp_state *g);
#ifdef GP_TEST_HOOKS                            /* PC tests only: kept out of the board build (the double return pulls in a libgcc helper) */
double gp_feature(const gp_state *g, int i);    /* feature i of the last window */
size_t gp_state_size(void);                     /* sizeof(gp_state) */
#endif

#ifdef __cplusplus
}
#endif
#endif
```

### Example: calling the chain from firmware
```c
#include "gesture_pipeline.h"

static gp_state g;                                  /* the whole state of the chain */

gp_init(&g, 3000000u, 0u);                          /* the timer's ticks per second; 0 = drop no start-up samples */
for (;;) {
    /* ... read x, y, z in milli-g and the timer's counter when the sample arrived ... */
    if (gp_push(&g, ticks, x_mg, y_mg, z_mg)) {
        printf("%s\n", GESTURE_CLASS_NAMES[gp_class(&g)]);
    }
}
```
`firmware/sparkfun_edge/gesture_demo/main.c` is the real thing: it sets up the accelerometer exactly as the logger does and prints one line per window.

## 2. The serial protocol (firmware version 1)

The gesture demo prints lines of text at 115200 baud, each ending in `\r\n`. Lines starting with `#` are comments; **a reader must ignore any `#` line it does not know.**

```
# sparkfun_edge gesture demo v1, whoami 0x33
# odr_hz=50 tick_hz=3000000 timer=hfrc3mhz window=128 step=64 features=40 classes=rest,shake_lr,shake_ud,circle,tilt
# columns: G,window,t_ticks,gesture,compute_us
G,12,123456789,rest,3812
# stats windows=20 overruns=0 i2c_err=0 restarts=0 ignored=0 max_compute_us=3900
# error: accelerometer init failed, code 1, whoami 0x00 (expected 0x33)
```

| Line | Meaning |
|---|---|
| `G,window,t_ticks,gesture,compute_us` | One completed window. `window` counts from 1 after a reset; `t_ticks` is the 32-bit counter (3 MHz) at the sample that completed it, and wraps about every 24 minutes; `gesture` is a name from the `classes=` list; `compute_us` is how long `gp_push` took for that sample (resampling, features and the model), in microseconds. |
| `# stats ...` | Every 20 windows: sensor overruns, failed reads, window restarts after a gap, repeated timestamps, and the slowest `compute_us` so far. All counts are since the reset. |
| `# error: ...` | A start-up failure, repeated every second. The firmware prints nothing else after it. |

Rules for anything that reads it:
- **Drop exact repeats.** Windows can hand over a stale buffer when a serial port is opened, which repeats the last line hundreds of times. A real stream never repeats a `(window, t_ticks)` pair.
- Expect cut-off lines at the start and in that stale flood.
- A change to the fields of a `G` or `# stats` line changes the version number in the first line (`v1`).

`tools/edge_gesture_monitor.py` is the reference reader; `python tools/edge_gesture_monitor.py --replay saved_output.txt` runs it without a board.

#### `tinyml_lab.edge_synth`: SYNTHETIC desk-gesture recordings in the capture-file format. NOT real data.

| Name | Parameters | What it does |
|---|---|---|
| `gesture_motion` | `(label, t, rng, amp, fscale)` | Motion acceleration (mg) in the hand's frame, shape (len(t), 3). Gravity is added separately. |
| `write_synthetic_gestures` | `(out_dir, sessions=3, seconds=45.0, seed=0, labels=..., rate_hz=51.22, orientation_sd_deg=20.0, recording_tilt_sd_deg=0.0)` | Write one capture-format file per (session, gesture). Returns the paths. |

#### `tinyml_lab.edge_features_c`: Compile the C feature code with the host compiler and compare it with the Python features.

| Name | Parameters | What it does |
|---|---|---|
| `find_gcc` | `()` | The path of a host C compiler ('gcc', else 'cc'), or None if there is none. |
| class `CFeatures` | `(real='float', workdir=None)` | The C feature code, built with the host compiler as 'float' or 'double' and called through ctypes. |
| `compare_features` | `(py, c, feature_set)` | How far apart two feature matrices are. Errors are measured against each feature's own size (its largest value). |
| `prediction_agreement` | `(X_py, X_c, y, sessions)` | How often a trained model answers differently on the float C features than on the Python features. |

#### `tinyml_lab.gesture_demo`: The desk-gesture chain as it will run on the board, held to the Python chain on the PC.

| Name | Parameters | What it does |
|---|---|---|
| `train_deployable` | `(data_dir, model='forest', feature_set='raw', seed=0)` | Train one model on EVERY recording. Returns (clf, X, y, labels, dataset). It has no held-out score by construction. |
| `model_sources` | `(clf, labels, feature_set, model)` | (gesture_model.c, gesture_model.h) for a trained model. The C function takes the features of one window. |
| `write_model` | `(clf, labels, feature_set, model, out_dir=..., ds=None)` | Write gesture_model.c, gesture_model.h and gesture_model.json into out_dir. Returns the JSON content. |
| class `CPipeline` | `(model_dir, real='float', workdir=None, extra_flags=())` | firmware/sparkfun_edge/gesture_demo/gesture_pipeline.c built with the host compiler and driven through ctypes. |
| `ticks_from_seconds` | `(t_s, tick_hz, start=0)` | The 32-bit counter values for sample times in seconds (as the board would stamp them). start: the counter at t = 0. |
| `python_chain` | `(t_s, xyz, clf, feature_set, skip=0, fs=50.0)` | What the Python code says for the same samples: resample, drop `skip` samples, cut windows, features, predict. |
| `compare_chains` | `(c, py, feature_set)` | The C chain against the Python chain on the windows both produced (the C chain may run on past the Python one's last window). |
| `check_recordings` | `(data_dir, clf, labels, feature_set, model_dir, real='float', skip=None, workdir=None)` | Run every usable recording under data_dir through the C chain and compare with the Python chain. skip defaults to the number of samples the Python dataset trims at each end, so both chains cut windows from the same samples. |
| `arm_footprint` | `(model_dir, workdir=None)` | Flash, stack and undefined symbols of the board build (Cortex-M4F, -Os, as the Apollo3 runs), or None without an ARM compiler. Nothing is run: these are sizes from the compiler. The stack figure adds the frames along the deepest call path (an estimate). |
| `build_host_sim` | `(model_dir, workdir=None)` | The real firmware main.c built for the PC against a fake board (host_sim/): a fake accelerometer replays a file of samples, the timer is each sample's own tick and the UART is stdout. Returns the executable. |
| `run_host_sim` | `(exe, ticks, xyz, flags=None, whoami=None, workdir=None, timeout=120, log=False)` | Replay samples through the simulated firmware; returns the lines it printed (and, with log=True, the log of what it configured and handed to the chain). flags: per-sample bit 0 = sensor overrun, bit 1 = status read error. |

#### `tinyml_lab.live_accuracy`: Live accuracy of the gesture model running on the SparkFun Edge: the board's own predictions scored against gestures done in a known order.

| Name | Parameters | What it does |
|---|---|---|
| `make_schedule` | `(labels=..., rounds=3, seed=1, block_s=20.0, pause_s=8.0)` | Blocks of one gesture each: `rounds` shuffled passes through the gestures, never the same gesture twice in a row. |
| `min_windows_per_block` | `(block_s=20.0, lead_in_s=2.0, tail_guard_s=0.5)` | The fewest windows that always fit in a block's scored zone, wherever the 1.28 s window grid happens to fall. |
| `timely_flags` | `(windows, tolerance_s=0.25)` | For each window (dicts with t_s, the PC arrival time, and t_ticks), whether it arrived on time. |
| `assign_windows` | `(windows, blocks, completed_s=None, lead_in_s=2.0, tail_guard_s=0.5, tag='')` | Decide which windows count. Returns (rows, dropped). |
| `evaluate` | `(rows, labels=..., seed=1, n_boot=2000)` | Score the counted windows: confusion matrix, accuracy, macro-F1, per-gesture recall and precision, per-block results and an interval. |
| `run_paths` | `(out_dir, session)` | (csv path, json path) of a run: <out_dir>/<session>_live.csv and .json. |
| `write_run` | `(out_dir, meta, windows)` | Save a run (the windows as CSV, everything else as JSON). Refuses to overwrite: every attempt is kept, none is replaced by a better one. |
| `read_run` | `(json_path)` | Load a run saved by write_run: (meta, windows). Unreadable CSV rows are skipped. |
| `score_run` | `(meta, windows)` | Place one run's windows in its blocks. Returns (rows, dropped, problems); problems are things that make the run less trustworthy. |
| `summary_text` | `(res)` | The result as plain text for a terminal (ASCII only, so a Windows console prints it). |

### The files of a live accuracy test
`tools/live_accuracy_test.py` writes two files per run into `data/own/edge_live/` and never overwrites them: `<session>_live.csv`, one row for every window the
board printed, and `<session>_live.json`, which says how the run was made. `scripts/evaluate_live_accuracy.py` reads both.

```text
t_s,window,t_ticks,predicted,compute_us
```

`t_s` is the PC time the line arrived, in seconds after the first window (the schedule's clock starts then). The rest are the board's own `G,` fields; `predicted`
is the board's gesture. The JSON holds these keys (`schedule` is a list of blocks, each with `index`, `round`, `target`, `start_s` and `end_s`):

```text
session, started_at, port, baud, seed, labels, rounds, block_s, pause_s, lead_in_s, tail_guard_s, schedule, completed_s, interrupted,
windows_received, stale_lines, stale_fragments, config_seen, board_config, monitor_problems, model, note
```

`model` names the model file in the repository (SHA-256, and what it was trained on) and says plainly that the tool cannot check that the board runs that file.

### Examples
```python
from tinyml_lab import edge_gestures as eg

ds = eg.load_dataset("data/own/edge_gestures")                 # every usable capture, as 128-sample windows

```

```python
from tinyml_lab import gesture_demo as gd

clf, X, y, labels, ds = gd.train_deployable("data/own/edge_gestures", "forest")      # trained on every session: it has no held-out score
gd.write_model(clf, labels, "raw", "forest", "my_model", ds)                          # gesture_model.c / .h / .json for the firmware
```

```python
from tinyml_lab import gesture_demo as gd

```
